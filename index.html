模型边界 简化教学测算，未纳入税费、汇率、仓配及其他费用；不能直接用于实际报价。所有金额均为模拟值。

  1. 先说清口径。成本 80、按售价计费 12%、目标利润率 20%。特别强调“利润率 = 利润 ÷ 售价”。
  2. 先算一行再做工具。让 Agent 给出公式、代入过程，再生成带输入框的单文件 HTML。
  3. 用反例检查。售价 50 元应亏损 36 元；空成本应报错；费率与利润率合计 ≥100% 应拒绝计算。
  4. 带走可复用指令。复制下方指令，把模拟数字换成你的业务规则，先校验再使用。
为什么是这个公式？展开推导与核验答案

利润 = 售价 − 成本 − 售价 × 费率。

两边除以售价，得到：利润率 = 1 − 成本 ÷ 售价 − 费率。

因此，售价 = 成本 ÷（1 − 费率 − 目标利润率）。

基础题：80 ÷ 0.68 ≈ 117.65
挑战题：100 ÷ 0.68 ≈ 147.06
反例题：50 × 0.88 − 80 = −36.00

04 / 04 · 钉钉 Agent

把 Agent 接进钉钉
让任务在群里闭环

工作发生在群里，Agent 也应该在群里接收指令、交付结果、@负责人并持续跟进。

接入不是多一个聊天入口

真正价值是把群消息、业务执行、文件交付、待办提醒和结果核验连成闭环。

为什么接入钉钉

让 AI 从「聊天窗口」
走进「业务现场」

同事无需切换工具：在群里给 Agent 指令，它完成任务后把文件、结论和异常提醒送回原群；需要人工接棒时，直接定向 @ 对应负责人。

普通聊天答案停在对话框

复制、发群、通知、追进度仍靠人工。

→
接入钉钉触发、执行、跟进连起来

群内下指令，Agent 执行并把下一棒交给对应的人。

→

→
04持续跟进与核验

到期提醒、收集回复，并回读消息或业务系统确认完成。

真实案例

群内定向 @

Agent 读取群成员身份，完成任务后真正 @ 对应成员；发送后回读消息，避免把普通文字误判为提醒成功。

业务交付

文件与摘要直接发群

群内收到需求后，Agent 执行、核验，再用机器人身份发送最终文件和精炼摘要。

定时任务

日报与异常提醒

每天到点取数、生成报告；发现缺货、逾期或执行失败时，主动在群里提醒相关成员。

场景拓展 · 会议纪要变待办

会开完，Agent 立刻接手下一步

把会议纪要发给群里的 Agent，它先提取明确承诺，再生成可追踪待办；缺少负责人或截止时间时不猜，而是在群里追问。

  1. 识别：决策、行动项、负责人、截止时间、验收标准
  2. 创建：将行动项写入钉钉待办，而不是只输出一段总结
  3. 通知：在原群真正 @ 负责人，附上任务、期限和来源纪要
  4. 追踪：到期前提醒；完成后回读待办状态并在群里收口
