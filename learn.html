02 / MAKE GOOD WORK REPEATABLE

把一次说对，
变成每次有据可依。

Skill 可以先理解为一份反复使用的任务说明：什么时候用、用什么材料、按什么规则做、交付什么、怎么验收。

{ }

从一份短规则开始，不必先写代码。

下面 3 份是适合新人阅读的教学 Markdown。可作为任务指令使用；如果产品支持 Skill，再按它的官方安装方式导入。它们不附带脚本，也不会自动授予系统权限。

01 / READ

只读查表

查库存、查到货、查进度。先说明对象、范围和来源，再返回有依据的答案。

  • 缺字段先指出，不自行补齐
  • 保留数据时间和来源行
  • 查不到时明确说查不到

03 / BUILD

分析小工具

从两张教学表生成汇总或本地网页，让结果可筛选、可解释、可核验。

  • 先明确关联键与公式
  • 缺失值不能默认为零

第一次怎么用？＋
  1. 打开一份规则，读一遍“适用任务”和“交付格式”。
  2. 在自己的 Agent 新建对话，粘贴规则，附上教学数据，再说明这次目标。
  3. 先做一个小样，按规则中的验收项检查结果。
  4. 反复使用时，再决定是否放进该产品的 Skill、项目指令或模板功能。不同产品的导入路径不相同。

无需安装，也能先测试规则是否写得清楚。Skill 是工作说明，不是已经接通 ERP、钉钉或文件系统的证明。

03 / CONNECT YOUR AGENT

让钉钉成为入口，
一段一段验证。

适用于已有可用 Agent 的同事。先确认产品支持的连接方式，再配置钉钉；用编造数据完成收发测试。

!
当前没有确认公司统一 AI 实验组织已开通。

开始前确认可使用的空白测试组织，以及你是否有创建、管理应用和发布版本的权限。若公司实验组织尚未开通，可按公司规则选择允许使用的个人空白测试组织；不在正式业务组织创建测试应用，不把业务数据或正式凭据带入实验。

截图来自既有课件引用的公开 WorkBuddy 指南，展示通用后台位置；实际菜单、权限和接收方式以当前钉钉及所用产品文档为准。

01

先让 Agent 在原入口回复你

发送：“请只回复：练习准备好了”。确认原产品能正常使用；再查该产品和当前版本是否提供受支持的钉钉连接器。

此步验收 原入口有实际回复；已找到对应版本的接入文档。没有钉钉支持时，先完成两表练习。
02

选测试组织，确认应用权限

在钉钉开放平台核对组织名称。确认是空白测试环境，你有应用创建与管理权限；界面没有创建入口时先核对权限，不切换到正式组织试。

03

创建应用，添加机器人

使用便于辨认的测试名称，例如“姓名 · Agent 练习”。进入应用能力，添加机器人并填写信息。名称和头像请与正式业务机器人区分。

此步验收 测试应用里看得到机器人能力。此时还不能认定已接通。
04

按你使用的产品配置连接

在产品官方指引中确认凭证字段、消息接收模式和必要权限。应用凭证只填到你自己的连接器配置中；不要发群，也不要截图展示真实密钥。

Stream / 长连接

核对连接器是否支持此模式，以及凭证、权限和启动要求；后台接收方式必须匹配。

HTTP 回调

需有文档要求的可达回调地址，并按产品说明配置校验参数；不要照抄另一产品的 Token 或 AES 设置。

查看各产品的准备清单 →
此步验收 配置和官方文档一致，连接器正在运行。状态绿灯只代表中间状态，仍需实际收发。
05

发布应用版本，核对可见范围

按当前后台流程创建并发布应用版本，等待需要的审批。确认测试人员属于应用可见范围；添加机器人能力和发布应用版本是两件事。

06

先私聊，再在测试群里 @它

在同一测试组织内搜索机器人，发送“请只回复：测试消息收到”。私聊实际收到回复后，再加入该组织的测试群并 @机器人发同样的消息。

最后再做一小题 粘贴编造的 3 行数据，让它只读求和并列出来源。聊天能回复不等于能读附件，更不等于已授权真实业务系统。

我使用 Hermes

先确认版本和受支持的连接方案

  1. 记录你实际使用的 Hermes 版本和运行方式。
  2. 查该版本的官方通道或连接器说明，确认是否支持钉钉。
  3. 记录文档要求的接收模式、凭证项、权限和启动方式。
  4. 找到连接日志与错误信息的位置，再开始通用后台步骤。

本课未核验你的 Hermes 版本与钉钉配置路径，因此不提供虚构按钮或“已接通”状态。

我使用其他 Agent

04 / YOUR QUESTIONS, CLEAR ANSWERS

从你的需求出发，
知道下一步验证什么。

来自观众收集表的具体问题。能用今天的方法起步，也有一些需要单独验证的接入与业务规则。

多系统取数、合表和自动报表，怎么开始？＋

先用导出的脱敏文件走通“关联键 → 异常 → 汇总 → 来源核对”。本课两表练习就是最小版本。之后再逐个验证系统取数权限、字段定义、更新频率与失败提示。

自动运行前，至少能回答：本次读了哪份数据、哪个时间点、是否漏行、失败时谁知道。漂亮看板的可信度来自这些细节。

先完成销售报告练习 ↗
市场日报能不能直接做竞品和实时广告坑位监控？＋

跨境资讯日报可以展示来源收集、核验、中文摘要和历史交付。特定竞品或广告坑位监控，还需要明确站点、页面、位置、频率、可获取的数据以及异常判定。

公开新闻汇总不能证明实时广告位监控已经可用。可先选一个公开页面和一个指标做小样，再验证稳定性与使用条件。

VC 资料提报、合规文件能不能自动处理？＋

可先拆成：资料整理 → 字段完整性核对 → 待补材料清单 → 人工复核 → 提交。目前应用清单没有提供完整 VC 提报链路的直接证据。

下一步需要真实模板的脱敏样例、规则依据、提交入口与授权范围。文件齐全不等于合规通过，生成文件也不等于已经提交成功。

紫鸟邮箱能不能自动回复？＋

可以先定义“分类 → 提取问题 → 生成草稿 → 人工确认”的任务。要自动发送，还需单独验证邮箱接入方式、收件范围、联系人识别、附件以及发送结果。

本次没有已经接通紫鸟邮箱的实证，因此把它作为后续小项目，不在现场承诺无人值守回复。

Windows 用户也能做这些吗？＋

这份课件和本地教学练习可在现代浏览器中打开。业务自动化是否支持 Windows，取决于具体产品、连接器与运行环境。

微软官方文档提供 Windows 上的 Copilot Studio computer use 和 Power Automate 桌面流程说明，证明 Windows 有相应路线；这不代表当前 Hermes 已经支持你需要的桌面客户端。先核对自己的产品与版本。

个人 Agent 怎样变成团队能用的能力？＋

先共享一份清晰的任务规则和教学样例，再明确维护人、版本、可使用范围与验收标准。团队共用接口还需要分别核对授权、操作记录、人员变更和失败处理。

群里能 @机器人，是协作入口；它本身不能证明多用户权限、审核与交接机制已经完整。今天的 3 份 Skill 可作为统一任务规则的起点。
