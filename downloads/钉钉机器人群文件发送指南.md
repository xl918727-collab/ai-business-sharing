# 让 Agent 以钉钉机器人身份向群里发送文件

> 目标：群里显示发送者为机器人（例如 Hermes），而不是企业组织身份或个人身份。

## 1. 创建企业内部机器人应用

1. 登录 [钉钉开放平台](https://open.dingtalk.com/)。
2. 进入「应用开发 → 企业内部开发 → 创建应用」。
3. 应用类型选择「机器人」，填写应用名称、图标和说明。
4. 在「权限管理」申请并通过以下权限：
   - `qyapi_robot_sendmsg`：机器人发送消息
   - `qyapi_chat_manage`：群会话管理
   - `ConvFile.File.Send`：发送群文件
5. 进入「机器人配置」，记录 `robotCode`。
6. 创建并发布应用版本。仅创建未发布时，机器人可能无法在目标群正常工作。
7. 在目标钉钉群的机器人设置里添加该机器人，并确认应用的可用范围覆盖目标群成员。

## 2. 取得目标群标识

打开 JSAPI Explorer：

https://open.dingtalk.com/tools/explorer/jsapi?id=10303

1. 点击右上角「开发者后台」，选择正确的组织。
2. 手机钉钉扫码登录。
3. 选择目标群并点击「运行调试」。
4. 保存返回的 `chatId` 和 `openConversationId`。

注意：这两个值不是一回事，不能混用。

- 会话类接口若要求 `chatId`，就传 `chatId`。
- 机器人群消息接口若要求 `openConversationId`，就传 `openConversationId`。
- 不要凭字段名称猜，按具体接口文档填写。

## 3. 配置 Agent

把以下配置安全交给 Agent，密钥不要写进公开网页、Skill 示例或共享文档：

- `AppKey` / `Client ID`
- `AppSecret` / `Client Secret`
- `robotCode`
- 目标群 `chatId`
- 目标群 `openConversationId`

建议保存在本机环境变量或 Agent 的私密配置中，并按组织、机器人和目标群分别命名，避免发错组织或发错群。

## 4. 文件发送链路

Agent 实际发送文件时应按下面的顺序执行：

1. 使用 AppKey + AppSecret 获取应用访问令牌。
2. 上传本次要发送的文件，取得平台返回的文件媒体标识。
3. 使用机器人群消息接口发送文件消息，并明确传入：
   - `robotCode`
   - 目标群 `openConversationId`
   - 文件媒体标识
   - 原始文件名
4. 发送完成后回读目标群消息，核对：
   - 发送者确实是机器人身份
   - 群标识与目标群一致
   - 文件名、日期、扩展名完全正确
   - 文件可下载，且不是旧文件或中间文件

## 5. 给 Agent 的任务指令模板

```text
请以已配置的钉钉机器人身份，把以下最终文件发送到指定群：
文件：/绝对路径/最终文件.xlsx
目标群：<群名称>

要求：
1. 使用机器人群消息接口，不使用组织身份或个人账号发送。
2. 仅发送最终文件，不发送处理中消息或中间文件。
3. 发送前核对目标群 openConversationId、文件名和文件日期。
4. 发送后回读群消息，确认发送者为机器人、文件名完全一致且文件可下载。
5. 任一回读不一致都不算完成，并明确报告未通过项。
```

## 6. 常见失败点

- 应用没有发布，或权限仍在审批中。
- 机器人未添加到目标群，或应用可用范围不包含相关成员。
- 把 `chatId` 和 `openConversationId` 混用。
- 只看到接口返回成功，却没有回读群消息核对实际发送者和文件名。
- 上传成功但群消息发送失败，上传媒体标识也可能已过期。
- 同一台机器配置多个组织时，AppKey、robotCode、群标识来自不同组织。
- Agent 复用了上一次任务的旧文件；应始终使用绝对路径并在发送前核对文件日期与内容。

## 7. 完成标准

只有以下条件全部满足，才算发送完成：

- 机器人身份正确
- 目标群正确
- 文件名正确
- 文件内容与本次任务一致
- 文件可下载
- 群消息回读证据已核对
