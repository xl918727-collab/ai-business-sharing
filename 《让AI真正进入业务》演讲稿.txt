《让 AI 真正进入业务》演讲稿

讲者：黎康杰 · 销售中心 三方渠道
建议时长：约 35 分钟


【封面】

大家好，我是销售中心三方渠道的黎康杰。

今天我不准备给大家上一堂工具课，也不想花时间解释 AI 有多少模型、多少参数。今天只回答一个问题：AI 到底怎样进入真实业务？

这里说的“进入业务”，不是让 AI 在聊天框里写一段看起来不错的文字，而是让它接到任务、找到正确的数据、按照我们平时认定数据的规则去做，最后交付一个真正能用、能核对的结果。

在准备这次分享前，我们收集了 75 份需求。我先带大家看一下，同事们真正关心的是什么。

（点击“看看 75 份需求里，大家最想解决什么”）

需求很集中：有人想打通多个系统和钉钉，有人想把表格做成看板，也有人最关心 AI 的准确性和检查结果对不对。

这些需求有一个共同点：大家缺的不是另一个只会回答问题的聊天机器人，而是一个能真正动手把事情做完的 AI 助手。

接下来我就用几个已经做出来的业务案例，展示它能做到什么程度。

（点击“开始现场实验”）


【第一章：先看 AI 能把业务做到什么程度】

这一页有三种完全不同的成果。

第一种是经营决策看板。

过去拿到交易报告、SKU 列表和广告数据，我们通常要先清洗，再统一计算规则，然后做透视表、图表和结论。现在可以把这些资料交给 Agent，让它按照经营逻辑生成一套能以后还能继续更新的看板。

这里不只是把数字画成图。真正有价值的是，它能把销售额、销量、广告成本、站点占比、SKU 动销和库存积压放进同一个页面。我们还可以像搭积木一样调整组件顺序、大小和展示方式。

（选择“经营决策看板”，视现场情况打开工具）

同一种搭建方法，也能用到新品销售、渠道积压、需要补货提醒和其他跨部门场景。

第二种是哆绘 AI 图像工作台。

它把过去需要反复沟通的修图流程，变成一句自然语言。比如：“保留产品结构，把背景换成明亮录音室，输出原图尺寸。”

它支持单图、多图和文件夹批量处理，也能带着参考图继续编辑。感兴趣的同事可以直接点击“打开哆绘”进入真实工具。

（选择“哆绘 AI 图像工作台”，需要时点击“打开哆绘”）

第三种是交互网页工坊。

给 Agent 一份产品资料，它不只能整理文字，还能做成可打开、可操作、可继续修改的网页。页面可以包含产品视觉、交互按钮、规格展开、手机适配，甚至三维模型。

（选择“交互网页工坊”，展示预览）

这三类成果分别对应三种业务价值：报表变成经营决策，文字要求变成视觉作品，产品资料变成交互体验。

这也是今天第一个结论：学 AI，不要先背功能。先看它能不能把你的材料变成一件真正可用的东西。

下面再往里走一步。一句话交给 Agent 之后，后台到底发生了什么？


【第二章：一句话之后，发生了什么】

表面上看，我们只发了一句话。实际要完成一项业务任务，Agent 至少要走四步：先弄清楚要做什么、找到数据、做出结果、检查后发回来。

先看“运营 · DDS 预到货问答”。

（选择“运营 · DDS 预到货问答”）

例如我们问：“EC7390 接下来到货时间。”

Agent 不能随便给一个日期。它要先识别产品、平台和站点，再读取允许它读取的数据，筛选仍在途、还没有入库的记录，最后把日期、数量和状态一起回答出来。数据不足时，它应该明确说没有查到，而不是补一个看起来合理的答案。

左侧展示的是机器人在真实群聊中的交付结果。右侧可以逐步回放它背后的处理过程。

（按需点击“回放机制”）

第二个案例是“物流 · SKU 标签与默认店铺维护”。

（切换到对应案例）

这类任务不是生成一段建议，而是要修改真实业务状态。Agent 需要核对平台、站点和 SKU，生成最终文件，完成维护后再再打开实际结果检查一遍。只有页面提示成功、电脑程序显示运行成功，都不算完成。最终数据真的改对了，文件也发到正确位置，才算完成。

第三个案例是财务九店交易报告。

（切换到“财务 · 九店交易报告”）

过去需要逐个店铺登录、设置日期、等待报表、下载并核对。现在可以在群里发一句话，由 Agent 在授权范围内批量执行，检查九个店铺是否齐全，再把结果送回指定群。

这里有两个容易被忽略的问题。

第一个是定时任务。定时任务当然是到点运行，但“到点运行”只证明系统已经在设定时间开始工作。对业务来说，我们还要确认本次文件已经生成、已经送达指定群，并且 Agent 又打开群消息，确认文件名和摘要都正确。

（展开“定时任务，怎么证明它真的交付了？”）

所以完整过程是：到时间自动开始，做出这次的文件，发到指定群，再打开群消息确认一遍。

第二个是准确性。

（展开“怎样让 Agent 的交付更准确稳定？”）

我的做法是检查两遍。负责执行的 Agent 做完后，先打开真实结果，自己检查一遍；再让另一个 Agent 按照最初的要求重新检查。两边都确认没问题，才交付。

这不是为了把流程搞复杂，而是因为 AI 最危险的状态，不是直接报错，而是很自信地告诉你“已经完成”。我们必须让“完成”有证据。


【第三章：让做成的能力可以复用】

一项任务跑通之后，如果经验只留在某个人的聊天记录里，下次还是要从头开始。

过去我们会手工写 SOP：回忆步骤、整理截图、补充异常情况。这个过程慢，而且业务一变化，文档很容易过期。

现在可以让 Agent 根据真实执行记录，自动整理成任务说明、操作步骤和成功案例。里面不仅有正常步骤，还要包含数据在哪里、要用什么工具、失败了怎么办，以及怎样才算完成。

（指向“过去、现在、交接、复用”的流程）

同事收到这份任务说明后，把它交给自己的 Agent。新 Agent 先学习业务规则，再检查还缺哪些数据、工具、系统权限和软件。准备好以后，先用一小份示例数据试跑，确认没有问题再执行真实任务。

这里要强调一点：新 Agent 一开始就是一张白纸。它不知道公司的口径，不知道数据在哪里，也不知道什么结果才算合格。我们不能期待它自己猜对。

页面下方这段学习指令可以直接复制给新 Agent。它会要求 Agent 先学习规则，列出缺少的东西，检查新工具是否安全，再用一小份示例数据试跑。正式执行以后，它会检查实际结果，再让另一个 Agent 检查一次。

（点击“复制指令”）

我们还做了一个共性能力复用库。

（点击“查看现有业务技能”）

里面不是空泛模板，而是已经在业务中做过的能力，例如库存汇报、预到货问答、经营看板、财报分析看板、SKU 标签维护、跨境资讯日报、eBay 月度经营复盘、预测准确率看板、退货与 VOC 分析、MSKU 映射、定价计算器和销售预测复盘。

大家不需要一次打开全部。先看用途，再打开自己真正需要的任务说明。

这些文件在共享前必须删掉敏感内容。客户和员工身份、店铺数据、SKU 明细、财务数字、账号、密钥、登录信息和内部链接都不能带出去。我们共享的是方法、结构和检查标准，不是敏感数据。

换电脑也一样。不是简单地说一句“备份”，而是导出一份内容清楚、可以逐项检查的迁移包：任务说明、操作步骤、业务规则、配置清单和所需工具。密钥和登录凭证不跟着打包。新设备导入后，要逐项测试。

做到这里，一项能力才真正从“这个人会做”，变成“团队可以复用”。


【第四章：把 Agent 接进钉钉】

前面讲的很多能力，如果最后都停在独立网页或聊天窗口里，业务使用成本仍然很高。

我们的工作本来就发生在钉钉群里，所以 Agent 也应该进入钉钉：在群里接收指令、执行任务、交付文件、提醒负责人，并继续跟进结果。

（展示“AI 走进业务现场”截图）

普通聊天的答案会停在对话框里。人还要复制、发群、通知、追进度。接入钉钉后，整个过程可以变成：在群里下指令，Agent 完成任务并 @ 负责人，随后持续提醒，再确认任务是否完成。

这里的“@负责人”不是在正文里打一个名字，而是让钉钉真的提醒到这个人。发送后还要重新打开群消息，确认提醒确实生效。

（展示群内定向 @ 案例）

文件交付也是一样。比如 SKU 标签维护完成后，Agent 把最终 Excel 和精简摘要直接发回业务群。同事不用再去另一个系统找结果。

（展示文件与摘要交付案例）

如果团队想配置这类能力，页面提供的是“Agent 在钉钉发送文件指引”。它不是普通的钉钉使用教程，而是告诉 Agent 怎样上传文件、发送消息，并在发送后重新检查群消息，确认文件真的送到了。

一个人也可以同时带着多个专职 Agent 工作。

比如“哆导”负责生图、图片编辑和视频制作；“isee”负责读取 DDS、分析数据并输出汇报。未来可以继续按业务分工创建专职 Agent。人负责目标、优先级和最后拍板，Agent 负责各自擅长的具体工作。

重点不在于 Agent 数量多，而在于每个 Agent 负责什么、能看哪些数据、做到什么程度才算完成，这些都要说清楚。


【结束】

今天展示的内容，可以浓缩成四句话。

第一，先从真实业务任务出发，不要从模型功能出发。

第二，一句话背后必须有完整过程：弄清楚要做什么、找到数据、做出结果、再检查一遍。

第三，任务做成以后，让 Agent 把经验整理成其他 Agent 也能照着做的任务说明，而不是把成功留在一次聊天里。

第四，把 Agent 放进团队真正工作的地方，让指令、执行、文件交付和后续跟进连起来。

AI 真正进入业务，不是因为它回答得像人，而是因为它能在清楚的使用范围和完成标准下，把事情做完，并留下可以核对的结果。

我的分享就到这里，谢谢大家。
